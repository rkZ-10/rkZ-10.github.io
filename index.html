Securing credential infrastructure at scale

Secrets Manager
Go · AWS KMS & DynamoDB · Diffie-Hellman key exchange
Problem

SysCloud's internal Secrets Manager API started with no real authentication at all — a free-text header stood in for a credential, brokering database connection strings, encryption keys, and service-account credentials to every internal service that asked.

Approach

First pass: credential-validated, 1-hour-expiry JWTs re-verified on every request across 15 protected endpoints, plus zero-downtime credential rotation. As part of a later company-wide hardening push, upgraded the whole system again to Diffie-Hellman key exchange, building a purpose-built client package and extending multi-tenant support for KMS-encrypted, DynamoDB-stored role data.

Outcome

Now serves 195 registered clients (124 Lambdas, 71 ECS stacks) across 10 teams and 7 AWS regions, processing ~9M requests/day at 99.9%+ success — the ~0.1% of rejections cluster predictably around the daily key-rotation window rather than reflecting real failures. 76 of 79 client credentials were rotated without a single service interruption.

Reliable fan-in signals for an unpredictable worker count

Sync Batch Tracking
Go · AWS SQS & DynamoDB · idempotent coordination
Problem

Bridging a legacy PHP sync system to a new Go watch-channel service meant answering one question reliably: when have all the parallel SQS sync workers for a batch finished — given that the worker count isn't known up front and any worker can fail partway through?

Approach

Built the fan-in point as atomic, idempotent DynamoDB counters, so the completion signal fires exactly once per run no matter the worker count or the order workers finish in. Before opening the pull request, a self-run audit caught defects that would have left syncs reading "in progress" forever; the team review that followed raised 9 more findings — 6 fixed, 3 pushed back on with reasoning the team accepted.

N workers, one counter, exactly one completion signal — regardless of N or finish order
Outcome

A correctness-critical coordination primitive now running in production with zero incidents since launch — the connective tissue between SysCloud's legacy PHP and modern Go systems.

An AI travel assistant, measured by evals

Personal project
MCP · RAG · Claude Agent SDK · FastAPI · React
Problem

Planning an Indian domestic flight means juggling live fares, airline fare rules, passenger-rights policy and personal preferences across several sites, and a plain chatbot will happily invent a fee or a rule.

Approach

Built a 9-tool MCP server for live fare search (Google Flights via SerpApi), day-of-travel status (AirLabs), saved preferences and policy search. Added a RAG layer over official IndiGo, Air India, Akasa and DGCA pages, using hybrid retrieval (SQLite FTS5 plus local bge-small embeddings) so every rule comes back cited and freshness-checked. A Claude Agent SDK planner ties it together with guardrails enforced in code, and a React and FastAPI chat UI shows live tool activity and flight cards that redirect to the airline's booking page. It never books or pays.

The chat UI: live tool activity, saved preferences applied, fare rules with sources
Outcome

A 23-case eval suite scores tool use, arguments, citations and whether every ₹ amount came from a tool, and the latest full run passes 23/23. The evals caught real regressions (such as quoting a pricier fare type's fee), which were then fixed. Runs locally on your own Claude login or API key. View the code on GitHub ↗
